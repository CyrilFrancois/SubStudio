# SubStudio: UI/UX review and target screens (2026-11-19)

**What this answers:** what is wrong with the dashboard for Cyril's three moments (one video now, a batch overnight,
watching the result) and which screens replace it. Companion of `architecture-review-2026-11-19.md`; read on branch
`feat/gemini-and-stop-job`. Statements about runtime behaviour are from reading the code unless marked measured.
**Cyril's process (`user-process.md` §1 and §5, D-0002) wins over this file:** select files, languages default
OV · EN · FR remembered between runs, Start; an overall progress bar plus a per-video stepper; a validated check per
video × language; output « Settings » below drops the sidecar default for the in-place update.

## 1. What the UI gets wrong

### The model it shows is the engine's, not Cyril's
Cyril thinks « this episode needs French subtitles ». The UI asks him for a Whisper size, a « pipeline logic », a
mux switch, an internal-subs switch, a sync offset, and a workflow per video, before showing whether French
already exists. The question it never answers: **which of my videos lack which language?**

### Concrete defects (file:line on the branch)
1. **Per-video choices are silently overwritten:** changing a global setting rewrites every video's languages and
   workflow (`page.tsx`, `setSettings` → `applyToAll`). A per-card override is lost with no warning.
2. **Two language lists:** the sidebar reads `NEXT_PUBLIC_LANGUAGES`, the card hard-codes
   `["en","fr","es","de","it","ja","ko","zh"]` (`VideoCard.tsx`). A language added in `.env` can't be picked per card.
3. **The output language picker opens on hover only** (`group-hover/multiselect`): unusable by keyboard or touch,
   and it closes when the pointer slips.
4. **Every log line shows the current time,** not when it happened: the timestamp is `new Date()` at render
   (`GlobalProgress.tsx`, `LogTerminal`). The empty terminal says « NOT WORKING, SEE YOUR BACKEND LOG » to the user.
5. **The progress bar goes backwards:** transcription reports 10→90 %, then translation restarts at 40→80 %, then
   mux at 90 % (`transcriber.py`, `translator.py`, `main.py`). The number means nothing across stages.
6. **A page reload loses everything:** selection, per-video settings, progress and logs live in React state only,
   and running jobs are not re-subscribed. An overnight batch can't be checked from a fresh tab.
7. **Dead and misleading controls:** SRC is a disabled « Auto-Detect » dropdown; « Legacy: SRT refining only »
   behaves like Hybrid; the model RAM labels (« Medium ~5 GB », « Large ~10 GB ») don't match int8 faster-whisper
   (well under that, hypothesis to measure); « Sync Files » means « rescan ».
8. **No way to see or check a result:** after « done » there is nothing to open: no cue list, no preview, no
   source/translation side by side, no way to fix one bad line or re-run one language.
9. **Batch blindness:** no queue, no order, no ETA, no history; the sidebar locks every setting while anything runs,
   so nothing can be queued behind it.
10. **Unreadable density:** 8–9 px labels (`text-[8px]`, `text-[9px]`), state shown by colour first.
11. **Strip existing subs** is one click on each card with no confirmation, while it removes tracks from the output.
12. **Scale:** one recursive scan runs ffprobe on every video on every « Sync »; no search, no filter, folders start
    collapsed, so a 500-episode library is a scroll-and-click marathon.

## 2. Target screens

### Library (home): the coverage matrix
- One row per video (grouped by folder/series, search box, filters « missing FR », « failed », « in queue »).
- One column per **wanted language** (set once in Settings). Each cell is a status chip with icon + text:
  `✓ original` (embedded/sidecar human), `✓ downloaded`, `✓ AI`, `— missing`, `⟳ running`, `! failed`.
- Primary action: **« Fill missing »** on the selection, a folder, or everything. The ladder of the architecture
  review decides how; no per-video engine choice needed. An « Advanced » drawer per video keeps the overrides
  (force ASR, choose the source track, sync offset), visibly marked when set.

### Queue: the overnight view
- Running job with a **stage stepper** (Find → Download/Extract → Transcribe → Translate → Write), each stage with its
  own bar and an ETA from measured bench speeds; queued jobs reorderable; cancel per job and « stop after current ».
- History (from the backend's job store, so it survives reloads): finished, failed with the reason in one sentence,
  time taken. Logs are per job, collapsible, timestamped by the backend.
- A small resource strip: loaded model, CPU/RAM against the half-machine budget.

### Review: watch and fix
- Video preview with the produced track (browser `<video>` + WebVTT for mp4/webm; MKV may not play in every
  browser: fall back to a waveform + cue timeline, hypothesis to test).
- Cue table: time, source text, translated text, editable; flags for long lines and too-fast reading speed;
  « re-translate this cue / this language »; « accept » marks the track reviewed.

### Settings
Wanted languages (one list, the only source for every picker), output (sidecar `Movie.fr.srt` by default, or mux),
speed/quality preset mapped to the benchmarked models, the resource budget, provider keys status (set / missing,
never the value).

## 3. What the frontend needs from the backend (contract to agree first)
- `GET /api/library` with per-video, per-language coverage (`state`, `origin`, `path`), cached by mtime.
- `POST /api/jobs` (videos × languages, options) → job ids; `GET /api/jobs` (queue + history); `DELETE /api/jobs/{id}`.
- `GET /api/events` one SSE stream for all jobs (`job_id`, `stage`, `stage_progress`, `eta_s`, log lines with
  backend timestamps) so a fresh tab picks up running work.
- `GET/PUT /api/subtitles/{video}/{lang}` cue list for the review screen.
- `GET /api/system` loaded model, CPU/RAM. `types.ts` generated from FastAPI's OpenAPI, not hand-mirrored.

## 4. How we will know it worked
- From opening the app to a running « fill missing French » on a folder: **≤ 3 clicks**, no engine setting touched.
- A reload during a batch shows the same queue and progress.
- Every failed job states its reason in one sentence on the Queue screen.
